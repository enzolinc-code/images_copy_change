# 实测踩过的坑（按性质归类）

## 提示词

- **模型只认具体名词**："换成更暖或更冷的邻近色系"✗ → "底色换成抹茶绿"✓；"点缀色换成对比色"✗ → "圆点从玫瑰粉改成深墨绿"✓；"点阵缩小约 30%"✗ → "改成细密小点（点径更小、数量更多）"✓。
- **文字让模型自己写**：本地字体仿母款那行字（Georgia → Courier 两版）都不像；把 `text.replace_from` 交给流水线生成强指令后，一次就对。模型对 3~8 个字母的英文短词可靠，**长商标词（如 Barbie）不可靠**。
- **局部重绘要有底稿**：把要重做的区域涂纯绿（`region_lock`），其余按像素保留；主体会被模型重画，所以区域锁定类子款出图后要用掩膜把母款主体**贴回**（否则猪会被画扁）。

## 指标与判定

- **"太像母款"不能用整幅灰度平均差**：手机壳画布上背景占大头，连"猪换兔子"都会被算成 0.95 相似。改成看**实际改动像素占比**。
- **通版图案不能用面积占比**：圆点只占几个百分点，换个母题也只动很少像素。改成三轴：母题像素变化 / 背景变化 / 排布周期（FFT 频谱相关）。
- **"太远"要换指标**：换底色（改动面积 0.88）比"整个换成别的设计"（0.69）还大，面积分不开；要用整幅结构相关。加了构图变异样本后这条轴在单主体款上**已无法用结构相关分开**，阈值只能取"只拦最不像的"，远端交人工。
- **构图变异要放行两类判定**："主体必须原位原尺寸""摄像头不能压主体"对构图为目的变异不适用 → 降级为警告不淘汰。
- **主体位移判定要比像素**：换底色会让 GrabCut 重算边界，bbox 与掩膜 IoU 都会假漂移。
- **子子去重同理**：整幅相关会把"猪换兔子"判成"困倦眼"的重复，改用差异面积。
- **阈值必须标定**：用人工标注（太像/刚好/太远）反推，别拍脑袋；标定口径要一致（同一类改动标同类，别自相矛盾）。
- **系统只拦"几乎没改动"的**，"改动够不够"交给市场。

## 工程

- **apply_patch 多文件补丁**：只要有一个 hunk 失败，**整批都不生效** —— 失败后要逐个文件确认是否改到，别直接往下跑。
- **不要把中文长句放进命令行内联脚本**（`python -c "..."`）：引号会被吃掉导致 JSON/语法错误。改成写文件或用 apply_patch。
- **写 JSON 时字符串里别用英文双引号**（要么转义要么用「」），我因此踩了两次 JSON 非法。
- **路径**：`D:\AutoTaobao\styles\`、`K:` 盘等不在可写根里，`apply_patch` 写不进去 → 先在项目内写好，再提权整体拷贝。
- **Windows 中文路径**：`cv2.imwrite` 静默失败/写出乱码名，必须 `cv2.imencode + tofile`；注意上游工具内部是 BGR，别当 RGB 再存一次（粉色会变紫）。
- **扩展名与实际格式**：jpg 直接改名成 .png 会被出图通道拒收（提交前失败，不扣费）→ 入库时解码后按真 PNG 落盘。
- **尺寸**：大改构图时模型会返回别的分辨率，出图后要按母款尺寸统一缩放，否则质检报尺寸不符。
- **子款编号**：重排计划时编号要从已有最大值往下排，否则会撞上旧子款、把记录改名覆盖。
- **批次目录**：重新导出前先清 `images/`，否则上一版被淘汰的图会留在目录里。

## 交付

- 交付目录只放最终版；`<名字>.png` 不许叠任何定位图形（壳体轮廓、角标、摄像头图形），定位信息只能在 alpha 通道。
- 一个设计一套；同名会互相覆盖 —— 出过的子款再生成要先查重名。
- 用户说"去掉后缀"是**改名，不是删图**。
